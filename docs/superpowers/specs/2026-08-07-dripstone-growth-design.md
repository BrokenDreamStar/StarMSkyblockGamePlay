# 滴水石锥加速生长 — 设计文档

日期:2026-08-07
状态:已批准(用户选择方案 A,速度目标约 100 倍)

## 背景与目标

原版滴水石锥生长极慢:生长基于随机刻,每接收到一个随机刻有 1.138%(64⁄5625)的概率生长一格,期望时间为 5 个游戏日(100 分钟)。空岛服务器玩家依赖滴水石农场获取滴水石锥、可再生岩浆(炼药锅填充)和黏土(泥巴转化),原版速度过于缓慢。

目标:将滴水石锥生长速度提升约 100 倍(期望约 44 秒/格),同时保持原版生长规则(生长条件、长度上限等)不变,并顺带加速钟乳石尖随机刻的其他原版效果(炼药锅填充、泥巴→黏土)。

## 原版生长机制(调研自 zh.minecraft.wiki)

- 钟乳石(倒挂滴水石锥)悬挂在滴水石块下方,滴水石块上方 1 格是水源方块(不能是水流)时,钟乳石可向下生长(最长 7 格),并在正下方非液体方块上生成/生长石笋,相接成石柱。
- 生长由**尖端方块的随机刻**驱动:每随机刻 1.138% 概率生长一格。
- 同一随机刻还负责:填充下方炼药锅(水 45⁄256、熔岩 15⁄256)、泥巴→黏土(45⁄256,下界除外)。
- 长度达到 7 格、尖端含水、下方被液体阻挡等情况下不生长。

## 方案选择

| 方案 | 思路 | 结论 |
|---|---|---|
| A(选定) | 定时扫描已加载区块找钟乳石尖端,调用 `Block#randomTick()` | 实现最简单、对所有已存在结构生效、与原版行为完全一致 |
| B | 事件索引跟踪钟乳石尖位置 | 开销小但索引维护边角情况多,易出 bug |
| C | 全局修改 `randomTickSpeed` 游戏规则 | 影响整个世界所有随机刻方块,破坏平衡 |

## 架构

新文件 `listener/DripstoneGrowthListener.java`,遵循现有 listener 模式:

- 构造器接收 `StarMSkyblockGamePlay` 插件实例,读取 config 的 `dripstone-growth` 段落。
- `StarMSkyblockGamePlay.onEnable` 注册 listener 并调用 `startGrowthTask()` 启动定时任务;`onDisable` 中取消任务(与 `VaultListener.startResetTask()` 同款模式)。
- 无命令、无持久化数据。

## 核心机制

**定时任务**(`BukkitRunnable`,主线程,每游戏刻运行一次):

1. 从 `getServer().getWorlds()` 按配置 `worlds` 过滤后轮询,每轮收集各世界已加载区块。
2. 每 tick 最多扫描 `chunks-per-tick` 个区块,区块游标(世界索引 + 区块索引)跨 tick 保持,一轮完成后重置。
3. 区块内三层循环遍历,寻找 `POINTED_DRIPSTONE` 且厚度为 `tip`、方向朝下的尖端:
   - 先 `block.getType()` 快速过滤,命中后才读取 `PointedDripstone` BlockData 判断 `thickness` 与 `verticalDirection`,避免全量对象分配。
4. 对每个命中的尖端调用 `block.randomTick()` × `random-ticks-per-pass` 次。
5. 生长条件判断完全交给原版逻辑,插件不重复实现。

### 为什么只扫描朝下的尖端

原版生长由钟乳石(倒挂)尖端驱动:石笋(正放)不会自行随机刻生长,只能由上方钟乳石促生。朝下的 `tip` 是唯一的生长驱动点,调用其 `randomTick()` 即完整复刻原版行为。

## 配置(config.yml 追加)

```yaml
# 滴水石锥加速生长(定期对符合条件的钟乳石尖触发随机刻)
dripstone-growth:
  # 是否启用
  enabled: true
  # 每轮完整扫描对每个钟乳石尖触发的随机刻次数(原版每随机刻 1.138% 概率生长一格,期望 100 分钟/格)
  random-ticks-per-pass: 10
  # 每个游戏刻最多扫描的区块数(控制主线程开销,0=不限制可能卡顿)
  chunks-per-tick: 1
  # 生效的世界(留空=所有世界)
  worlds: []
```

任务每轮从 config 重新读取参数,`/starmskyblockgameplay reload` 无需特殊处理即可生效。

## 性能

默认配置下,假设 100 个已加载区块:

- 一轮完整扫描 = 100 ticks = 5 秒。
- 每个尖端每秒触发 10/5 = 2 次随机刻 → 生长期望 ≈ 87.9 / 2 ≈ 44 秒/格(原版 100 分钟/格,约 100~136 倍)。
- 扫描开销:每 tick 1 个区块的 `getType()` 遍历(天空岛区块多为空气,开销小);`chunks-per-tick` 可调,`random-ticks-per-pass` 可调生长倍率。

## 边界与错误处理

- 扫描过程中区块卸载 → `chunk.isLoaded()` 守卫,跳过。
- 世界加载/卸载动态变化 → 每轮重新获取世界与区块列表。
- 只对已加载区块生效(原版随机刻本来也只作用于加载中的区块)。
- 所有操作在主线程执行,无并发问题。
- `onDisable` 取消任务,防止重载残留。
- `Block#randomTick()` 为 Paper 26 API 正式方法,由 `./gradlew build` 编译验证在 26.1.2 的可用性。
